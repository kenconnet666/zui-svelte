# Core 性能基线与门槛

第一份基线来自 a8cf60f 的 CI 35299462819：Linux、Node 24.20.0、Intel Xeon Platinum 8573C。完整样本、SHA、来源链接与预算保存在 [预算文件](core-performance-budget.json)。

| 工作负载                | 基线 p95 | 同环境回归门槛 |
| ----------------------- | -------- | -------------- |
| 10,000 次稳定结构更新   | 75.41ms  | 250ms          |
| 1,000 实例各 100 次更新 | 806.18ms | 2,500ms        |
| 100 轮挂载/销毁         | 2.48ms   | 50ms           |

前两项约留三倍调度与实现余量；极短用例使用 50ms 下限避免 CI 调度噪声。此门槛用于发现明显回归，不代表期望消耗，也不是浏览器帧预算。修改门槛必须说明原因与新旧证据，不能为单次失败临时放宽。

脚本先预热再采集五次，报告完整样本、p50/p95 和环境。只有 CPU、平台和 Node 主版本与基线一致时阻止耗时超标；不同机器标记为不可直接比较，继续记录。升级环境后另建基线。

所有环境都必须满足：提升后不再编译本地规则；千实例的初始静态规则共享；后续规则/变量记录有界且值不串用；释放后绑定、规则、来源与样式记录归零。

这份基准消费实际 core/dist 产物，测的是 Node 端计算与 MemoryStyleSheet。浏览器 DOM、首屏、真实 CSSOM 与包体积仍需 P7 的独立证据，不以本表替代。CI 输出保存在 core/test-results/benchmark.json，并随验证报告上传。
